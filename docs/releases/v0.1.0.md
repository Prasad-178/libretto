# Libretto v0.1.0

First tagged GitHub source release, licensed under [MIT](../../LICENSE).

Libretto lets developers define, test and run voice-agent workflows in YAML, with Studio as the visual editor and debugger. Developers own their application tools, provider credentials, data and deployment.

## Included

- Importable Python core: YAML compilation, explicit tool contracts, request-scoped state, confirmation/readback guards, cancellation and session-local action identities.
- Two substantive fictional examples: Northline front desk and repair visits, plus a small core-only support-request starter.
- Offline scenario CLI with assertions, redacted evidence, structured blocked-action explanations and read-only Studio replay/navigation.
- Studio visual authoring for the supported YAML settings, source-preserving edits, optional layout sidecars, knowledge inspection and separate model/STT/TTS configuration.
- Optional LiveKit Agents 1.8.10 integration using Studio's custom PCM/WebSocket transport. Direct Deepgram remains available.
- Developer quickstart, installation profiles, compatibility boundaries and migration notes.

## Install from GitHub

For the Git install commands below, use Python **3.12+**, Git and uv:

```sh
uv venv --python 3.12
uv pip install --python .venv 'libretto-voice @ git+https://github.com/Prasad-178/libretto.git@v0.1.0'
```

The distribution is `libretto-voice`; imports use `libretto`. The package version is **0.1.0**. This release uses GitHub/source distribution; no package-registry publication is part of the release. Optional extras are `providers`, `livekit` and `studio`.

Start with the [quickstart](../quickstart.md). The installed core wheel contains Python modules and its license, while examples/Markdown and built Studio assets remain source-checkout resources. For Studio setup, use the CI-tested Node **24** major and the documented frontend build. See the compatibility guide for dependency engine ranges.

## Verification and limits

The release process requires passing hosted CI on the exact commit targeted by `v0.1.0`. Automated coverage includes isolated core installation, compiler/runtime authority, offline scenarios, synthetic speech adapters, frontend tests and Chromium browser checks. The packaging regression checks version 0.1.0, MIT metadata and inclusion of the license in the wheel.

**Real-provider voice acceptance remains pending.** Provider authentication, live recognition/synthesis quality and acoustic interruption behavior are not established by mocked or scripted tests. User Studio review and three outside-developer adoption trials also remain pending.

Actions in the bundled demos are simulated. There is no durable session/reconnect recovery or durable exactly-once side-effect guarantee. Real business integrations need application-owned idempotency/recovery. Unknown action outcomes are not automatically retried. The current voice integration does not establish WebRTC room playback guarantees.

## Compatibility and migration

Use the [compatibility/setup guide](../compatibility.md) and [request-policy migration](../migrations/request-policies.md) when updating an older checkout. YAML schema, scenario input, Studio sidecar and evidence formats are separate version-1 contracts; the Python package version does not replace them. Back up application definitions and lockfiles and run your scenarios against registered tools before switching versions.

Earlier source commits also reported package version 0.1.0. Use this tag or its exact commit to identify the MIT-licensed release baseline. Dated milestone reports retain the scope and limitations of their original verification; they are not a later release verdict.
