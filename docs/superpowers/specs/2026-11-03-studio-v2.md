# Libretto Studio v2 design specification

Status: implementation complete on `feat/studio-v2`, with deferred minor gaps recorded in [the implementation review](../studio-v2-review.md). Local verification is separate from hosted CI and deployment.

## Product and scope

Libretto is a developer-oriented YAML voice-workflow tool. Studio opens, inspects, edits, validates, tests and exports a developer's workflow. Northline is one fictional example, not a required graph shape or domain model.

This iteration implements the Studio experience and the local-project APIs it requires. It does not publish to PyPI, build the optional LiveKit integration, or claim that the current receptionist-specific runtime is already a general-purpose library. The provider-independent library API and LiveKit adapter remain a separate subproject. Existing voice/audio behavior must keep working during the Studio migration.

- [Flow, Routes, inspectors, testing and generic workflow patterns](https://app.paper.design/file/01M6A0TRXN4CJ9WFK05YH6CX0W/p-3-0)

## Document contract

- Keep the imported UTF-8 bytes and original filename. A no-op export is byte-identical, including BOM, CRLF/LF, comments, block scalar style and final newline.
- Raw YAML is the single executable source of truth. Forms, graph operations, Settings and source-usage changes are document transactions, not independently maintained workflow copies.
- Untouched text remains untouched after form edits. Never automatically reflow prompt paragraphs, fold literal blocks, or normalize line endings. Preserve every unchanged prompt string exactly.
- Invalid drafts remain editable. Keep the last successfully validated workflow for Flow/Routes and show the last-valid banner. Do not fall back silently to the original Northline workflow. A backend-unavailable state is different from an invalid definition.
- Undo/redo covers document transactions, including graph insertion and source detachment. Coalesce typing in one field into a history entry until blur or another command. A new edit clears redo.
- Validation responses are bound to the exact source revision/request. Ignore stale responses. Status differentiates validating, valid/unexported, exported/unchanged, invalid and validation unavailable.
- A test uses an immutable validated source snapshot. Pause executable-document edits while it runs; selecting steps and inspecting evidence remains available. Stop test once, retain transcript/trace, then resume editing.

## Schema, identities and runtime truth

- Nodes use existing `title`, falling back to a humanized ID. Add optional edge `label`; retain existing YAML compatibility.
- An edge's stable identity is `{source, edgeId}`. Edge IDs are unique only within their source node. React Flow IDs may use `JSON.stringify([source, edgeId])`.
- Use the same route label in pills, Exits, Routes and Trace. Predicate summaries belong in details/tooltips, not a different route name.
- Preserve current evaluation semantics: matching predicates precede language matches; YAML order breaks ties within a kind. Action nodes select matching result routes. Say nodes follow their outgoing continuation.
- An edge with both a predicate and language condition does not currently enforce AND. Show a precise legacy-mixed explanation in advanced/raw YAML; do not offer an AND editor or silently change runtime semantics.
- Conversation insertion must collect an author-specified continuation condition. Action insertion must map declared tool results. Only Say is automatic. Do not copy the current unqualified `continue` edge into every inserted kind: the runtime cannot follow it for conversation/action nodes.
- Insertion on a protected `before_action` route remains disabled, with an explanation and a usable earlier insertion point.

## Graph and editing

- Respect the current bounds: 1–64 nodes, up to 256 transitions, 100,000 source characters. UTF-8 byte preservation is an additional file concern, not a replacement for the API character bound.
- No mandatory router, three-intent layout, named lanes, wrap-up node or single sink. Preserve every declared terminal; a cycle-only workflow must not acquire a synthetic End.
- Use structural layout: SCC analysis, acyclic ranking, stable input order and explicit return edges. Reuse installed Dagre/React Flow before introducing another layout engine. Positions and group visibility do not change executable behavior.
- Node previews are compact. Actions have a neutral surface and tool name. Blue means editing selection; green means the current test step.
- A visible connector is a real route or explicitly labelled bundle. Shared trunks may share a source or target. Each route/bundle keeps a label on its stub; different unrelated routes must not share ambiguous geometry.
- Destination chips use `Label → Target`. First activation inspects the route; a separate action/modified activation jumps to the target. Hover/focus can draw a temporary dotted preview.
- All routes is the default. Overview/named views are explicit saved presentations; never infer runtime likelihood. Hidden routes retain `N more` controls and the complete Routes index. Keep failures represented by default.
- Inserting a node or editing a prompt should not reflow unrelated pinned nodes or reset viewport zoom. Fit is an orientation action; the normal reading view starts at 100% and may scroll/pan.
- Right inspector: title/ID/type, prompt or action configuration, information fields, Exits, Incoming, Advanced. Exits never filter with the graph view. Prompt expansion is an internal wide editor.
- Routes lists all transitions, canonical labels, kind, condition, destination, nondefault timing and canvas placement. A selected row can reveal its route on the canvas.

## Sources and project ownership

- Sources is collection → files → passages → usage/retrieval. One display name everywhere; show the stable source ID once in developer context. Source display names belong to optional Studio metadata, with a humanized-ID fallback.
- `Filter files` filters filenames. `Test retrieval` is a distinct main collection action and uses the selected step's effective knowledge scope.
- Effective sources are the union of `common_knowledge` and the selected node's `knowledge`. Changing global scope is a visible YAML edit, not an invisible negative override.
- Show ranked results, result count/limit, matched normalized terms and passage identities. Highlight matches without inserting markup into source content. Selecting a result opens/highlights the corresponding passage.
- Use the same local keyword retriever as the runtime, with a maximum of three passages for this UI. No cloud ingestion, crawler, embeddings setup or generated answer is implied.
- Missing folders currently produce zero passages; show an actionable warning and do not incorrectly call the YAML invalid. Unconfigured/out-of-root paths in hosted mode are rejected separately.
- Folder selection chooses an existing folder within the runtime's explicitly configured project root. It edits a relative YAML reference and copies/deletes no files. Browser-only hosted mode cannot inspect a developer's filesystem.
- Hosted capability flags must disable unsupported folder actions with a local-setup path. Do not render working-looking controls backed by fictional results.
- Removing a collection removes its common/per-node references atomically. Explain affected steps, leave files intact and offer Undo.

## Metadata, export and Settings

- For `northline.yaml`, the optional shared layout is `northline.studio.json` beside it. Open explicitly selects that file; do not claim automatic neighboring-file discovery in a browser.
- Shared sidecar data: schema version, source fingerprint, pinned positions, groups, source display names, named route views and presentation overrides. Route references use structured identities.
- Stale references are ignored with a cleanup notice. Deleting a sidecar cannot change workflow behavior or prevent YAML from opening.
- Device preferences include inspector width, temporary selection/collapse state and runtime endpoint. Never persist credentials in localStorage, YAML, sidecar or exported transcripts.
- Export lists exact filenames, one diff per executable change in YAML order, and a button matching the files selected. A downloaded file is not proof that a project file was overwritten.
- Explain that Studio cannot detect external changes to a browser-imported project file: reopen before replacing if it changed outside Studio.
- Settings: Conversation; Models & speech; Fields & tools; Test connection · This device. Model/provider options come from runtime capabilities, not a hardcoded claim that every provider is installed.
- Response model and Route evaluator are distinct. Reasoning applies to the response model. Tool implementations live in the runtime registry; YAML references tools and configures per-action arguments/requirements/results.
- Field usage lists actual predicate/action references, not guessed collection ownership based on prompt prose.

## Responsive and accessibility contract

- At 1440: 400px inspector. At 1280: 360px inspector and Open YAML in filename menu.
- At 1024: 380px drawer, no scrim, Escape closes it. Sources/Settings navigation becomes a select. YAML Problems is a 200px bottom strip; Routes folds canvas placement into a labelled icon/control.
- Below 1024: explain that Studio editing needs a wider viewport. Keep the homepage responsive.
- Tab/Enter selects steps/routes; E cycles exits including hidden ones; Escape restores focus. Distinguish selected, active, pending, error and disabled states without relying on color alone.
- Respect reduced motion. Verify clipping, focus visibility, scroll ownership and controls at 1440×900, 1280×900 and 1024×900.
