# Libretto Studio v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task in this session. Use checkbox steps. Do not delegate unless separately authorized.

**Goal:** Implement the agreed 23-screen Studio experience with reliable YAML editing, a generic workflow graph, useful Sources/Settings, and truthful testing/export states.

**Architecture:** Keep raw YAML in one document store and derive graph/form views from validated revisions. Separate graph semantics/layout from rendering, preserve existing voice/session code behind a test-panel boundary, and expose local Sources through a capability-aware backend API. Reuse React Flow, Dagre, CodeMirror and `yaml`; no state-management or graph-engine replacement is planned.

**Tech Stack:** Existing React 19, TypeScript, Vite, React Flow, Dagre, CodeMirror, `yaml`, FastAPI/Pydantic, local BM25; Vitest/pytest plus Playwright for integrated browser behavior.

**Spec:** [Studio v2 specification](../specs/2026-11-03-studio-v2.md)

## Global Constraints

- Studio remains `/studio`; retain the current homepage and audio/session behavior.
- Preserve imported bytes on no-op export and untouched prompt values after edits. Do not mistake serializer round-tripping for byte preservation.
- Current bounds remain 1–64 nodes, 256 transitions and 100,000 source characters.
- Northline remains one fictional example. No graph/domain assumptions based on its names.
- Preserve predicate-before-language evaluation; do not promise AND for mixed legacy edges.
- Respect host/local capability boundaries. No filesystem access, provider support or tool registration is inferred from a visual control.
- No PyPI publication, LiveKit adapter implementation, deployment or extra external design review in this plan.
- Make meaningful regular commits using normal hooks. Stage explicit files; retain unrelated untracked design/review documents.
- Execute inline. Implementing this plan is a separate action from preparing it.

## Baseline and sequencing

Planning baseline: local commit `33b1521`. The existing UI lives mainly in `web/src/App.tsx`; `Studio.tsx` is only a re-export. `WorkflowGraph.tsx`, `StepInspector.tsx` and `AgentEditor.tsx` already provide reusable behavior. Current `editValue`/`setYamlValue` serialize the whole document; current `insertStep` gives every kind an unqualified continuation that conversation/action execution cannot use. Fix those contracts before redesigning controls around them.

The existing server always loads the bundled receptionist; `libretto serve <workflow>` currently ignores that workflow argument. Sources only exposes bundled passages. The companion [local project/Sources plan](2026-11-03-studio-sources-runtime.md) handles that independent subsystem.

## Shared interfaces

Task 1 owns `FlowEdge`, `RouteRef` and presentation helpers. Task 2 owns the document store and transaction API. Task 3 owns sidecar/export artifacts. Tasks 4–8 consume those interfaces instead of maintaining independent workflow copies.

```ts
export type RouteRef = { source: string; edgeId: string };
export type RouteKind = "language" | "state" | "result" | "automatic" | "legacy-mixed" | "unconfigured";
export type YamlPath = readonly (string | number)[];
export type TextPatch = { from: number; to: number; insert: string };
export type EditOperation =
  | { op: "set"; path: YamlPath; value: unknown }
  | { op: "delete"; path: YamlPath };
export type DocumentTransaction = {
  label: string;
  operations: readonly EditOperation[];
  historyGroup?: string;
};
export type WorkflowIssue = {
  path: readonly (string | number)[];
  message: string;
  severity: "error" | "warning";
  from?: number;
  to?: number;
};
export type ValidatedRevision = {
  revision: number;
  source: string;
  workflow: Workflow;
};
```

`Workflow`/`FlowNode` describe the actual schema: node kinds are a union, optional YAML properties stay optional, and omitted End edges are an empty list in derived views only. Include reasoning, speech, field choices and edge labels; avoid widening everything to `any`.

Task 1 creates the following shared declarations in `web/src/studio/types.ts` so subsequent tasks do not depend on files that have not been implemented yet. Import `Workflow` from `../workflow` and keep these as type-only declarations. Task 2 owns state transitions; Task 3 owns metadata validation/IO.

```ts
export type Point = { x: number; y: number };
export type SavedView = { id: string; name: string; visibleRoutes: RouteRef[] };
export type StudioMetadata = {
  version: 1;
  sourceFingerprint?: string;
  positions: Record<string, Point>;
  groups: { id: string; label: string; members: string[] }[];
  sourceNames: Record<string, string>;
  views: SavedView[];
  presentation: { target: string; mode: "auto" | "lines" | "chips" }[];
};
export type DraftSnapshot = { source: string; metadata: StudioMetadata };
export type StudioDocument = DraftSnapshot & {
  filename: string;
  importedBytes: Uint8Array;
  importedSource: string;
  revision: number;
  lastValid: ValidatedRevision | null;
  validation: {
    requestId: number; revision: number;
    state: "idle" | "pending" | "valid" | "invalid" | "unavailable";
    issues: WorkflowIssue[];
  };
  past: DraftSnapshot[];
  future: DraftSnapshot[];
  historyGroup: string | null;
  exported: { source: string; at: number } | null;
  running: ValidatedRevision | null;
};
export type DocumentAction =
  | { type: "transaction"; transaction: DocumentTransaction }
  | { type: "raw-source"; source: string; historyGroup?: string }
  | { type: "metadata"; metadata: StudioMetadata; label: string }
  | { type: "end-history-group" | "undo" | "redo" | "test-stop" }
  | { type: "validation-start"; requestId: number; revision: number }
  | { type: "validation-result"; requestId: number; revision: number; source: string;
      workflow: Workflow | null; issues: WorkflowIssue[] }
  | { type: "validation-failure"; requestId: number; revision: number }
  | { type: "test-start"; snapshot: ValidatedRevision }
  | { type: "export-recorded"; source: string; at: number };
export type RouteDescriptor = {
  ref: RouteRef; target: string; label: string; kind: RouteKind;
  condition: string; predicate?: unknown; result?: string;
  timing: "next_response" | "before_action";
};
export type RoutePresentation = {
  refs: RouteRef[];
  mode: "drawn" | "chip" | "hidden" | "bundle";
  target: string;
};
export type GraphLayout = {
  nodes: { id: string; x: number; y: number; width: number; height: number }[];
  routes: { ref: RouteRef; points: Point[]; labelPoint: Point }[];
  unreachable: string[];
  bounds: { x: number; y: number; width: number; height: number };
};
```

Decode imports with fatal UTF-8 validation and preserve BOM information; use `TextDecoder("utf-8", {fatal: true, ignoreBOM: true})` for source and keep the original bytes independently. Only Say's empty-condition continuation is automatic. An unqualified conversation/action exit is `unconfigured`, with an explanation that it cannot fire under the current runtime; do not label it Always.
