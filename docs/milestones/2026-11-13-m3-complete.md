# M3 executable testing and debugging — local completion

**Status: implementation complete and verified locally.** Hosted CI at a pushed head and any demo deployment remain separate, unverified external gates. M2 real-provider voice acceptance remains pending by owner choice. This does not assert release/merge readiness from local tests alone.

## Developer path delivered

1. Install the core from source/Git without Studio, a provider SDK or credentials.
2. Write a strict YAML/JSON scenario with scripted evaluation proposals, simulated tool contracts/results, delivery/interruption controls and assertions.
3. Run `libretto test <file-or-directory> [--json] [--output evidence.json]`; get correct 0/1/2 exit status and checkpoint failures with actual observed behavior.
4. Change the workflow, observe a failing test, repair it and see it pass. The automated author-path regression proves this against the real compiler/runtime.
5. Open a saved run in Studio, inspect state and reason codes at each event, and navigate to the exact connection or staged confirmation rule when the source hash matches. Read-only replay cannot start providers or tools.
6. Inspect a live test's observed blockers/unknown outcomes in State/Trace. During a test, connections remain read-only and rule editing requires Stop. Late results cannot replace the current request's diagnostic.

## Boundaries and next milestone

Scripted evaluation proposals test execution rules, not a model's interpretation quality. Delivery steps simulate the public acknowledgement boundary, not actual heard audio. Saved replay is manual event inspection, not automatic rerunning or audio playback. The source commit plus dirty marker is provenance, not a complete dependency/environment capture. Redaction is not anonymization; metadata IDs/configuration and non-designated data may identify an application. Live-export files are intentionally distinct from scripted replay bundles.

M4 next focuses on source-install usability, compatibility/release documentation and actual outside-developer trials. License selection remains the owner's decision before reusable-release claims. No package-registry publication, account system, billing, collaboration, hosted agent platform or outside contact is authorized by this milestone. The public demo may be updated only through a separately requested deployment.
